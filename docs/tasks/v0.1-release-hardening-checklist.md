# M26 v0.1 Release Hardening Checklist

This is the active implementation checklist after M25. The product is the embedded
browser application started by the single executable. Historical M20-M24 daemon,
CLI, and mailbox plans are not active backlog.

## Scope Guardrails

- [x] Keep one product surface: the loopback Web application backed by the existing
  execution library.
- [x] Do not add a provider protocol, tool family, daemon, registry, mailbox, TUI, or
  second chat runtime in M26.
- [x] Treat durable session items as canonical and SSE run events as bounded live
  presentation state.
- [x] Prioritize user-recoverable lifecycle behavior, browser regression coverage,
  and reproducible release artifacts over architecture refactors.

## P0 Closure

- [x] Add execution and Web API support for restoring an archived session.
- [x] Load archived sessions separately from active sessions in the browser.
- [x] Let users expand archived sessions, restore them, or permanently delete them.
- [x] Keep archived sessions out of the active selection and prevent opening them
  before restore.
- [x] Test archive/list/restore behavior in execution, Web API, and browser flows.
- [x] Add browser coverage for first-project setup and configured session creation.
- [x] Add browser coverage for a text-only streaming run and durable committed result.
- [x] Add browser coverage for cancellation without a persisted failed turn.
- [x] Add browser coverage for active-run recovery and durable resync.
- [x] Preserve the existing history pagination and viewport-anchor browser tests.
- [x] Mark the abandoned M21 checklist and mailbox task-board proposal as historical.
- [x] Record M26 as the single active milestone in stable documentation.

## Product Lifecycle UX

- [x] Add session rename to the Web UI using the existing Web API.
- [x] Add project rename to the Web UI using the existing Web API.
- [x] Add project archive/remove controls with running-session protection and clear
  confirmation of affected sessions.
- [x] Decide whether archived projects need restore in v0.1; do not expose project
  archive as a one-way UI action.
- [x] Cover the final project/session lifecycle behavior in Playwright.

v0.1 does not expose project archive as a standalone browser action. Project removal
shows the total saved-session impact, archives internally, then permanently removes
the project and its sessions. If removal fails after archive, the browser attempts to
restore the project before refreshing the active project list.

## Behavior Test Coverage

- [x] Cover bootstrap metadata, security headers, loopback Host validation, Origin
  validation, SPA fallback, and strict JSON request handling at the Web boundary.
- [x] Cover Web lifecycle failure mapping for missing resources, destructive-action
  preconditions, and project/session mutations blocked by an active run.
- [x] Cover the append-active prompt API from queue publication through removal and
  settled-run rejection.
- [x] Cover provider create/update/default/model-discovery behavior through the Web
  API, including secret redaction and stable error envelopes.
- [x] Cover execution provider persistence, retained secrets, validation, sorted
  model discovery, and Codex auth save/status/clear behavior.

At P2 closure, `go test -cover ./internal/webapp ./internal/execution` reports 65.1%
statement coverage for `internal/webapp` and 67.2% for `internal/execution` (up from
50.4% and 59.6%, respectively). The assertions target public behavior and API
contracts; the percentages are recorded as evidence rather than treated as a
substitute for those assertions.

## Release Automation

- [x] Add a tag-driven GitHub release workflow for `v*` tags.
- [x] Run backend, frontend, browser, and embedded-asset freshness checks before
  publishing artifacts.
- [x] Build Windows amd64, Linux amd64, and macOS arm64 with the tag injected into
  `internal/webapp.Version`.
- [x] Generate and publish SHA-256 checksums with the three binaries.
- [x] Execute the Linux artifact's `--version` and verify the injected tag marker in
  every cross-compiled artifact before publishing.
- [x] Document the supported target matrix and any platform-specific launch warning.

## Release Smoke

- [ ] Start the actual packaged executable with a temporary Server Root.
- [ ] Use a local fake provider so the smoke does not require credentials or external
  network access.
- [ ] Register a project, create a session, receive a streaming response, and verify

- [ ] Cancel a blocking fake-provider run and verify the session remains usable.
- [ ] Archive and restore the smoke session.
- [ ] Record commands and observed evidence in a release smoke document.
